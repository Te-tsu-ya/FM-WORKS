# CTO向けの経理・資金繰り確認

GitHub内の架空データだけで、通常の経理画面と金融機関別入力台帳を操作します。Googleへのログイン、スプレッドシート、npmインストール、GitHub Actionsは不要です。

## 起動

Node.js 20以上を用意し、このリポジトリのルートで実行します。

```sh
node scripts/start_demo.mjs
```

ブラウザーで `http://127.0.0.1:4173/#finance` を開きます。ポートを変更する場合は環境変数 `FM_DEMO_PORT` を設定してください。サーバーは自分のPCだけからアクセスできます。

## 確認する流れ

1. 経理 → 経費台帳で300件の架空明細を確認します。通常の経費入力・承認・精算も同じ画面から操作できます。
2. 経理 → 資金繰りで「金融機関別入力台帳」を開き、金融機関を選びます。
3. 「＋ 入力行を追加」で、日付 → 摘要 → 出金 → 入金 → 残高 → 分類 → メモの順に縦方向へ入力します。実績／予定を最後に選びます。Excelのタブ区切りの複数行貼り付けにも対応します。
4. 日付は西暦の年月日、金額は整数の円単位です。入金・出金はどちらか一方を入力します。残高は任意。「実績の残高を計算」は保存済みの最新残高から、新しい実績行を日付順に計算します。過去へ挿入する行は手動で残高を確認します。
5. 「入力を保存・年間へ集計」で保存し、「年間資金繰りを見る」で全金融機関の12月～翌11月を確認します。たとえば2026/10/13に1,000円の実績入金を保存すると、2026-10の実績入金が1,000円増えます。予定は予定欄へ入ります。
6. 同じ送信を再試行しても二重登録しません。保存結果が不明な間は入力を固定し、同じ入力で再試行します。

未保存行は集計されません。実績・予定を無条件に合算しません。明細未取込月は「未取込」で、実績の年間合計は取込済み分です。保存済み銀行明細の金額は読み取り専用です。分類・メモの見直しは既存の分析画面で行います。

## 同梱データ

`demo/data/financial.json` は外部ファイルからコピーせず、`scripts/generate_repository_demo.mjs` が名前・金額を組み立てた架空データです。

| 対象 | 件数 |
| --- | ---: |
| 金融機関 | 3 |
| 銀行実績明細 | 318 |
| 入出金予定 | 360 |
| 経費台帳 | 300 |
| 経費精算 | 60 |
| 出張 | 12 |

2026年11月期（2025年12月～2026年11月）を例にしています。実績の基準日は2026年10月13日です。経費・精算・出張には予定日を含む画面説明用の行もあります。領収書ファイルや原本の顧客・金融機関・金額は含めません。

説明用の変更はブラウザーのセッションごとのサーバーメモリーへ保存します。別ブラウザーには共有されず、サーバー再起動で初期状態へ戻ります。JSONファイル、実際のスプレッドシート、Google Driveへは書き込みません。基準データを作り直すには、リポジトリのルートで `node scripts/generate_repository_demo.mjs` を実行します。

## 実装の共有と本導入

`demo/server.mjs` が通常のHTMLを組み立て、`demo/runtime.mjs` が既存GAS関数にメモリーの保存先を渡します。金融機関登録・台帳保存・予定・分類・年間集計は `src/` の実処理を使います。認証はこのローカル説明環境だけの架空管理者です。本番GASの認証を変更・解除しません。

今回の確認対象は経理・資金繰りの入力と集計です。他メニューは既存の画面を表示しますが、ローカル版はAPIを限定しています。外部ファイル発行、メール、打刻登録、すべての他部門操作、GAS公開は対象外で、未対応の操作はエラーを表示します。

CTOと本導入を相談する際は、共有DBの候補、権限、同時更新、監査、バックアップ、添付資料の保存先を決めます。GitHubのJSONは説明用の初期データであり、複数人が使う本番の保存先ではありません。要件・現在のGAS構成・入力から集計への関係は `docs/REQUIREMENTS.md` と `docs/TECHNICAL_DESIGN.md` に記録しています。

## 検証

```sh
node scripts/run_local_checks.mjs --functional
```

GPT環境で実行し、GitHub Actionsは使いません。HTTP/APIと計算の検証はブラウザーでの表示検証とは区別します。GAS公開版へ反映する際は、認証済みの直接操作またはローカルclaspと公開URLでの確認が別途必要です。
