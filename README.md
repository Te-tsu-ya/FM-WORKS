# FM WORKS

## 勤怠管理アプリ（GAS公開URL）

**[FM WORKS アプリを開く](https://script.google.com/macros/s/AKfycbw7oWIZkrOE-ClTVNeI0Kq4hzsZrYaKSC0CqNVsV4bwpufgBVR5-7MYxVEuj_51A9YgvQ/exec)**

公開先は既存のGoogle Apps Scriptウェブアプリです。GitHub Actionsによるデプロイ後は、このURLから動作確認してください。

Fusion Mind社内向けの統合ワークポータルです。

## 主な機能

- 社員番号 + PINログイン / セッション管理
- 出勤 / 退勤 / 休憩 / 勤務場所
- 工数入力・編集・削除 / プロジェクトマスタ
- 共有予定表（月 / 週 / 日 / 一覧）
- 会社カレンダー（一般社員は閲覧、権限者のみ編集）
- 有給 / 半休 / 1/4日有給 / 欠勤 / 打刻修正 / 在宅 / 残業 / 休日出勤の申請・承認
- 社員マスター / 権限管理 / 仮PIN再発行
- 月次勤怠集計 / 給与対象者一括Excel出力 / 税理士提出用文面
- PIN再発行依頼 / サポート連絡先
- 監査ログ
- 本番運用チェック（PIN・会社カレンダー・バックアップ・試作モード）
- 月次の休憩不足 / 工数差異チェック
- 月初の先月勤怠本人確認 / 変更後の再確認アラート
- 月次カレンダー確認 / 日別修正導線
- ライト / ダークテーマ
- ADMIN向け要件定義書 / 技術設計書ビュー
- ソース変更時の設計文書同期CI
- 高速初期シェル + 非同期ホーム概要でログイン後の待ち時間を削減
- 段階的メニュー先読み / 管理保守APIの遅延読込
- ライブ実働時間 / ホーム集計の再読込復旧 / キーボードショートカット
- PC向け1画面ホームダッシュボード（予定・打刻履歴のみ内部スクロール）
- 経理メニュー（ADMIN・経理・総務限定）、経費記録、社員の経費精算・出張報告、承認・差戻し・精算状況（DB更新後）

## 技術構成

- Frontend: HTML / CSS / JavaScript
- Backend: Google Apps Script (V8)
- Data: Google Sheets「FM WORKS DB」
- Export / Storage: Google Drive
- Source control: GitHub
- Deployment: clasp + GitHub Actions

## 認証・セキュリティ

- PINは平文保存せず、社員別Salt + Script Properties上のPepperを使ったHMAC-SHA256で保存
- セッショントークンもハッシュ化して保存
- セッション絶対期限 / アイドル期限
- ログイン失敗回数制限 / 一時ロック
- 仮PINは初回変更必須
- 権限チェックはUIだけでなくApps Script側でも実施
- 打刻・ログイン・PIN変更・申請・主要管理操作を監査ログへ記録
- GitHubへPIN / OAuthトークン等の秘密情報をコミットしない

## 権限

- `ADMIN`: 管理機能を含む全機能
- `CALENDAR_EDITOR`: 通常社員機能 + 会社カレンダー編集
- `USER`: 自分の勤怠・工数・申請、共有予定表、会社カレンダー閲覧

## 本番公開前の必須手順

1. アプリを `MYSELF` のまま開き、初期ADMINのPINを設定
2. 設定画面で「PINを忘れた場合」の連絡先を設定
3. 各社員へ仮PINを発行
4. 認証後にWebアプリ公開範囲を社内運用向けへ変更
5. PC / スマホでログイン・打刻・申請・月次のE2E確認

## デモ・検証データ

現在のFM WORKS DBに登録している社員名・顧客名・プロジェクト名・予定詳細は、画面検証用の架空データです。
旧勤怠ファイル自体は変更せず、FM WORKSへ取り込んだスナップショットだけを匿名化しています。

- 架空社員: `FM0001 青木 悠真 / FM0002 森川 彩乃 / FM0003 神谷 直人 / FM0004 小林 美月 / FM0005 中村 健太`
- 架空プロジェクト: `Project Atlas / Project Nova / Project Orion / Project Bloom / Project Vega / Project Aurora / Internal Works`
- 顧客表示: `顧客A / 顧客B / 顧客C`
- 実際の社員名・顧客名・案件名をGitHubへハードコードしない
- 画面・テスト・サンプルデータに表示する人物名と案件名は、上記の架空データだけを使用する


## 経理機能（v0.13.0）

- 管理者が既存の「管理 → 運用」からDB更新を行って初めて経理用3シートが作られます。更新処理は既存のバックアップ機構を通ります。
- 参考Excelの実データは移行しません。オリジナルExcelも編集しません。
- 社員は「申請」から自分の経費・出張を登録します。ADMIN・経理・総務は「経理」メニューで記録・確認・承認・精算状態を管理します。
- 現金出納帳や仕訳帳の作成、銀行振込、レシート画像アップロード、電子証憑の法令対応保存、会社規程に基づく自動日当計算は未実装です。

- 自動品質確認: `node scripts/test_finance_integration.mjs` が架空データによる申請・承認・精算・権限・証跡テストを実行します。CI・Deployの必須ゲートです。


## v0.13.1 本番DBを変更しないデータ連携デバッグ

- Google Sheets「FM WORKS DB」の既存ヘッダー構造を参照し、申請列名の不整合を修正。既存値・列順は保持。
- 経費・出張の差戻し後再申請、承認時詳細確認、証憑番号による経費と申請の金額照合を追加。
- DB更新前に既存の見出し不一致を検査し、想定外の構造に対する部分的更新を防止。
- 承認待ち優先表示、追加読込、長期日付期間の範囲外混入防止を追加。
- 変更の検証はGitHub ActionsのCIで行い、本番DBの移行・データ更新は自動実行しない。


## v0.13.2 画面高速化

- 画面遷移の描画を優先し、月次集計の二重通信を解消。

## v0.15.1 データ読み込み最適化

- 同一Apps Script実行内のスプレッドシート接続を再利用。
- 認証用の行位置を再利用しつつ、実際の権限・有効期限を毎回確認（認証の省略なし）。
- 実GASの所要時間は別途検証。

- 工数の日付移動は対象月と前後1週間のキャッシュを使用し、月境界でも再通信を減らします。

## v0.16.0 見積書の使い方

- 見積書→新規見積を作成を開き、左側の取引先・件名・条件・明細を入力します。右側の帳票プレビューが即座に更新されます。
- 明細は追加・複製・並び替え・削除できます。下書き保存後に「正式発行」を押すと、発行済み詳細からPDF・Excelをダウンロードできます。
- 初回のみ見積DBが未初期化なら管理者が「バックアップして見積機能を有効化」を実行します。管理・設定→見積・取引先では1社ずつの登録と過去発行番号の確認ができます。
- プレビューは参考表示です。従来のExcel原本との完全一致は原本再取得後に突合する必要があります。

### v0.16.1 発行済み見積の確認

発行済みの詳細画面は、入力中と共通の帳票レイアウトで表示します。宛先は発行時に保存した名称・住所、金額は発行時に保存した数値を表示し、後日の取引先マスタ変更で過去の見積内容が変わらないようにしています。
