# FM WORKS 要件定義書

**文書版:** 0.8.1  
**更新日:** 2026-10-07  
**正本:** GitHub `docs/REQUIREMENTS.md`

## 1. 目的

FM WORKSは、社員の勤怠、工数、予定、申請、会社カレンダー、月次確認、管理を一つのWebアプリに統合する社内向けワークポータルである。

本書は、別のエンジニアが本書と技術設計書だけを読み、同等機能を再実装できる粒度で機能要件・業務ルール・画面要件・非機能要件を定義する。

## 2. 対象ユーザーと権限

| ロール | 主な権限 |
| --- | --- |
| USER | 自分の勤怠、工数、申請、月次確認。共有予定表・会社カレンダー閲覧 |
| CALENDAR_EDITOR | USER権限 + 会社カレンダー編集 |
| ADMIN | 全機能。社員・認証・承認・プロジェクト・運用設定・設計文書閲覧 |

管理系APIは画面制御だけに依存せず、Apps Script側で必ず再認証・再認可する。

## 3. 画面構成

### 3.1 共通ナビゲーション

左サイドバーに以下を表示する。

- ホーム
- 勤怠
- 工数
- 予定表
- 会社カレンダー
- 申請
- 社員
- 月次
- 設定（ADMINのみ）

ADMINの設定配下に以下のサブメニューを表示する。

- 運用設定
- 要件定義書
- 技術設計書

### 3.2 1画面完結方針

- PCでは月次・設定を1ビューポート内に収める。
- 情報量が多い表・文書はページ全体ではなくパネル内スクロールを使う。
- スクロールしなければ主要操作に到達できない構造を減らす。
- モバイルは画面幅の制約を優先し、必要な場合のみ縦スクロールを許容する。

### 3.3 クリック視認性

- ボタン、カード、日付セル、セレクト、ナビ、クリック可能行はポインタカーソルを表示する。
- 独立したポインタ操作対象は原則24×24 CSS px以上を確保し、小型ボタンは28px以上を基本とする。
- ホバー時に背景・枠・影のいずれかが変化する。
- キーボード操作時は `:focus-visible` を明確に表示する。
- 色だけで状態を伝えず、文言・アイコン・バッジを併用する。

## 4. ライト / ダークテーマ

- ライト、ダークの2テーマを提供する。
- 初回はOSの `prefers-color-scheme` を参照する。
- 以後はユーザーが選んだテーマを `localStorage` に保存する。
- 切替時は約0.5〜0.7秒かけて色・背景・グラデーションが滑らかに移行する。
- 対応ブラウザではView Transition APIを利用し、非対応ブラウザはCSSトランジションへフォールバックする。
- `prefers-reduced-motion: reduce` の場合は大きな演出を抑制する。

## 5. 認証

### 5.1 ログイン

- 社員ID + 6桁PIN。
- 試作モードでは架空社員 `FM0001〜FM0005` のみ共通PIN `000000` を許可できる。
- 本番モードでは社員ごとのPINのみ。
- 「この端末でログイン状態を保持する」をONにした場合は最大30日保持する。

### 5.2 PIN保護

- PIN平文保存禁止。
- 社員別Salt + Script Properties上のPepper。
- HMAC-SHA256でハッシュ化。
- 失敗回数制限と一時ロック。
- 仮PINは初回変更必須。

### 5.3 セッション

- ブラウザには生トークン。
- DBにはトークンハッシュのみ。
- absolute expiry / idle expiryを持つ。
- ログアウト、PIN変更、社員無効化、試作モード終了時に失効する。

## 6. 勤怠

### 6.1 打刻種別

1. 出勤
2. 休憩開始
3. 休憩終了
4. 退勤

勤務場所は `出社 / 在宅 / 外出`。

### 6.2 打刻順序

サーバー側で順序検証を行う。

- 退勤前に出勤が必要。
- 休憩終了前に休憩開始が必要。
- 重複出勤など不正遷移を拒否する。

### 6.3 打刻修正

- 元打刻を物理更新・削除しない。
- 修正レコードを追加する。
- 元打刻IDとの関係を残す。
- 承認操作と監査ログを必須とする。

### 6.4 休憩チェック

- 実働6時間超: 45分以上。
- 実働8時間超: 60分以上。
- 不足は月次の要確認理由にする。

## 7. 月初の先月勤怠確認

### 7.1 自動アラート

- 毎月1日以降、前月の本人確認が完了していない社員へアラートを出す。
- アラートはホームだけでなく全画面上部に表示する。
- 通知メニューにも「勤怠確認」を出す。
- 確認完了するまで継続表示する。
- 月が変わっても未確認月を消さず、`MONTHLY_REVIEW_START_MONTH` 以降の未確認・再確認月を古い順に案内する。
- 1つの月を確認完了した後、未確認月が残っていれば次の対象月を自動表示する。
- `MONTHLY_REVIEW_DUE_DAY` の既定値は5日。
- 1日〜期限日はwarning。
- 期限超過後はdanger。

### 7.2 再確認

確認後に対象月の以下が更新された場合は、確認済みを再確認状態として扱う。月をまたいでも再確認義務を失わない。

- 打刻
- 工数
- 申請
- 会社カレンダー

### 7.3 確認完了条件

本人が自分の過去月を確認する。

確認完了ボタンは以下が0件の場合だけ有効。

- 要確認日
- 工数差異日

ADMINが月次画面で他社員を選択した場合、その社員の本人確認状態を読み取り専用で表示する。ADMINが本人確認を代理完了することはできない。

確認時に以下を記録する。

- 年月
- 社員ID
- 氏名
- 状態
- 確認日時
- 確認者
- 確認時最終更新
- メモ
- 登録日時
- 更新日時

## 8. 月次画面

### 8.1 表示モード

- 既定: カレンダー
- 切替: 一覧

### 8.2 カレンダーセル

各日セルに以下を表示する。

- 日
- 出退勤 / 休暇 / 要確認理由
- 実働
- 状態点

状態:

- 正常
- 休暇
- 工数差異
- 要確認
- 休日

### 8.3 日詳細

日付クリックでモーダルを開く。

表示:

- 会社カレンダー区分
- 出勤
- 退勤
- 休憩
- 実働
- 残業
- 工数
- 勤務場所
- 問題理由

導線:

- 打刻問題 → 対象日を引き継いで打刻修正申請
- 工数差異 → 対象日の工数画面

### 8.4 月次サマリー

1画面内に以下をコンパクト表示。

- 実働
- 残業
- 有給
- 欠勤
- 要確認日
- 工数差異日

## 9. 工数

- 進行中プロジェクトから選択。
- 作業内容必須。
- 開始・終了必須。
- 同一社員・同一日の重複時間帯禁止。
- 削除はソフトデリート。
- 月次締め済み月は追加・編集・削除禁止。
- 実働との差が5分超の場合は月次で工数差異。

## 10. 予定表

- 月 / 週 / 日 / 一覧。
- 予定カードに社員名を直接表示。
- 社員色は補助情報。
- カテゴリ色とは分離。
- 複数人は先頭2名 + 残人数。
- 色だけで担当者を判断させない。

## 11. 会社カレンダー

- 登録済み年度だけ表示。
- 未作成年度は自動表示しない。
- 権限者が「YYYY年を作成」を押した時点で生成。
- 初期生成は土日・国民の祝日。
- 会社独自休日・年末年始・調整出勤日は人が確認して修正。

## 12. 申請

申請種別:

- 有給
- 午前半休
- 午後半休
- 1/4日有給
- 欠勤
- 打刻修正
- 在宅勤務
- 残業
- 休日出勤

画面要件:

- 「何を申請しますか？」のクイックカード。
- 選択後は必要項目だけ表示。
- 有給系は現在残 / 承認待ち / 申請可能残 / 今回消化 / 申請後残数。
- エラーはフォーム内に具体的に表示。
- エラー項目へフォーカス。
- Toastは補助に留める。

## 13. 有給

- 有給残日数は0.25日単位。
- 実値不明なら仮値を設定しない。
- 未設定は明示。
- 承認待ち分を申請可能残から差し引く。
- 不足する申請は申請前に拒否する。

## 14. 月次締め

ADMINのみ。

締め前条件:

- 給与対象者1名以上。
- 要確認勤怠0。
- 工数差異0。
- 承認待ち申請0。

締め後:

- 工数追加・編集・削除停止。
- 対象月の申請承認停止。

解除:

- ADMINのみ。
- 理由必須。
- 監査ログ必須。

## 15. 社員

社員マスタ項目:

- 社員ID
- 氏名
- 表示名
- 部署
- 役職
- 権限
- 在籍
- 標準勤務開始
- 標準勤務終了
- 標準休憩
- 有給残
- メール
- 備考
- PIN関連
- 給与集計対象

## 16. 設定

ADMINの設定画面をタブ化する。

- 認証・サポート
- プロジェクト
- 運用設定
- 要件定義書
- 技術設計書

プロジェクトタブでは、既存プロジェクトの一覧・編集と新規追加を行えること。設定画面の再構成によってこの機能を失わないこと。

### 16.1 要件定義書・技術設計書

- ADMINのみ閲覧可能。
- GitHub Markdownを正本とする。
- デプロイ時にApps Script用データへ生成。
- アプリ内で見出し、表、リスト、コードを読みやすく表示。
- 「再読込」はクライアントキャッシュを無視し、現在のデプロイ文書を再取得する。

## 17. 文書同期ルール

- `src/**` の変更を伴うコミットは、同じコミットで `docs/REQUIREMENTS.md` と `docs/TECHNICAL_DESIGN.md` の両方を更新する。
- GitHub Actionsで検査する。
- 片方でも未更新ならデプロイ失敗。
- 文書版と `APP.version` を一致させる。
- UI変更、業務ルール、データ構造、API、セキュリティ、運用変更はすべて文書反映対象。

## 18. 性能

- メニュー切替はキャッシュ済み画面を即時表示。
- ログイン後、主要画面をアイドル時間に先読み。
- 重複通信を抑止。
- Google Sheets呼び出しは一括読込・一括書込を優先。
- Apps Scriptサービス呼び出し回数を最小化。

## 19. エラー

- セッション切れ: ログインへ戻す。
- 一般操作: Toast。
- 入力: モーダル内エラー。
- 具体的な業務理由を表示。
- 色だけに依存しない。

## 20. バックアップ

- DBバックアップ保持90日。
- 管理者利用時に1日1回を基本。
- 手動バックアップ可能。

## 21. 受入条件

1. 月初に前月未確認アラートが全画面で表示される。
2. 確認完了後に対象月のアラートが消える。
3. 確認後のデータ変更で再確認アラートが表示される。
4. 月が変わっても古い未確認月が消えず、最古の未確認月から順に案内される。
5. 月次をカレンダーで確認できる。
6. 日付から打刻修正または工数確認へ移動できる。
7. ADMINだけが要件定義書・技術設計書を読める。
8. ソース変更コミットで両設計文書が未更新ならCIが失敗する。
9. ライト・ダークの選択が保存される。
10. テーマ切替が滑らかに見える。
11. PCの月次・設定は長いページ全体スクロールを必要としない。
12. クリック可能箇所はポインタ・ホバー・フォーカスを持つ。
13. 既存機能に回帰がない。
14. 設定 → プロジェクトで一覧・追加・編集が正常に動作する。
15. ADMINが他社員の月次本人確認状態を確認できる。
16. 設計文書の「再読込」が実際にサーバーから再取得する。
