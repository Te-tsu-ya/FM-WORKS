# FM WORKS 要件定義書

対象：v0.0.3 / 更新：2026-10-21

## 1. 目的と範囲

日々の勤怠・工数・案件・予定・申請と、経理・資金繰り・総務・文書を一つのアプリで扱う。現在動いているSites＋SQL版を基準とする。旧公開方式や過去の説明資料は現行仕様の根拠にしない。

現在は開発専用。架空の担当者・案件・金額・文書で動作を確認する。正式な社員認証、会社規程の制定、給与計算、税務提出、電子帳簿の法令対応を完了した製品として扱わない。

## 2. 基盤の要件

| ID | 要件 | 受入条件 |
|---|---|---|
| R01 | ソースはGitHub `Te-tsu-ya/FM-WORKS`のmain | 統合したソースと公開したSitesのソース内容が一致する |
| R02 | 公開はGPT Sites | 同じSiteへ更新し、公開結果を確認する |
| R03 | 永続保存はSites内蔵SQL/D1 | 別のHTTP要求から保存済みの値を取得できる |
| R04 | データはすべて架空 | 実業務データを取り込まず、ダミー生成元を管理する |
| R05 | 公開し直してもデータを維持する | 既存DBの初期化・seed再投入を行わない |
| R06 | 他の画面の更新を消さない | 改訂不一致の更新を409で拒否し、部分書込みを残さない |
| R07 | 権限をサーバーで検証する | ログイン切れ・トークン不一致・権限外操作を拒否する |
| R08 | 未対応の操作を成功扱いしない | 対応前のファイル発行などは501と理由を返す |

現在のSiteは許可されたGPTアカウントに限定して共有する。作業開始時にSitesの現在の閲覧・編集対象を確認し、更新公開ではその範囲を維持する。対象者の追加・削除は明示されたときに変更する。

初期データは5担当者、6案件、3金融機関を含む1,864行。経費・取引・予定・申請・備品・文書などに見本を用意する。初期値であり、現在のDB件数は操作により増減する。

## 3. 利用者と権限

Siteへの入場制限と、アプリ内の架空担当者の権限を分ける。担当者選択は開発用であり、本人確認には使用しない。

| 対象 | 現在の制御 |
|---|---|
| 全担当者 | 自分の勤怠・工数・申請、予定、会社カレンダー閲覧、案件、本人の見積 |
| リーダー（MANAGER） | 上記に加え、直属部下の月次確認・申請承認。自己承認は不可 |
| 管理者（ADMIN） | 社員・会社カレンダー・マスタ管理、資金繰り、管理文書など |
| 経理・総務担当 | 部署条件を満たす場合に経理・総務の管理操作。管理者も操作可能 |

見積は作成者本人と管理者が閲覧・操作する。予定は社内・参加者のみ・管理者のみの公開範囲を持つ。詳細は[運用・開発ルール](RULES.md)と`src/domain/core.js`・各領域の権限検証を参照する。

## 4. 現行機能

「接続済み」は画面とAPI・SQLの経路があることを示す。全操作の実画面検証完了は意味しない。

| ID | 領域 | 操作と必要な振る舞い | 現在の状態・制約 |
|---|---|---|---|
| F01 | ログイン・ログアウト | 架空担当者選択、セッション開始・終了 | SQLセッションと公開先HTTPで確認済み。PIN認証は使用しない |
| F02 | ホーム・通知 | 当日の状態、月の集計、未処理事項の確認 | SQL取得を検証済み |
| F03 | 勤怠 | 出退勤・休憩・勤務場所、履歴、修正申請 | 打刻のSQL保存を検証済み。不正な状態遷移を拒否する |
| F04 | 工数 | 日付・案件・作業・時間の入力、期間別取得 | 保存・再取得をローカルと公開先で確認済み |
| F05 | 予定・会社カレンダー | 月週日表示、予定保存・削除、参加者・公開範囲、勤務日 | 予定と勤務日のSQL保存を検証済み |
| F06 | 申請・承認 | 有給・半休・欠勤・打刻修正・在宅・残業・休日出勤、取消 | プレビュー・承認ルールを継承。休暇申請保存を検証済み |
| F07 | 社員月次・有給 | 本人確認・締め・再開、有給台帳・残数 | SQL取得経路あり。全承認・締め・自動付与の実画面確認は未完了 |
| F08 | プロジェクト | 案件、計画、作業、進捗、資料、依存、原価・予算 | 一覧・詳細取得を検証済み。ファイル添付は未対応 |
| F09 | 見積・関連書類 | 取引先・明細の入力、下書き保存・再取得 | 見積下書きのSQL保存を検証済み。正式発行・ファイル取得は未対応 |
| F10 | 経理 | 経費記録、精算・出張申請、審査・支払・再申請 | 経費集計取得を検証済み。インボイス外部照会と帳票出力は未対応 |
| F11 | 資金繰り | 11月末決算の年度、銀行明細貼付・台帳、予定、注記・分類・照合・シミュレーション | 分析取得と一般社員のアクセス拒否を検証済み。Excel/CSV提出物生成は未対応 |
| F12 | 総務 | 備品・貸出・購買・書類・契約・施設・依頼 | 備品・契約等のSQL取得を検証済み。全保存経路の受入は未完了 |
| F13 | 社内文書 | 本文・分類・フォルダー・タグの管理と検索 | 架空文書取得を検証済み。ファイル保管は未対応 |
| F14 | 設定・管理文書 | 社員・案件・見積マスタ、要件・設計の閲覧 | 現行SQLへ接続。旧認証・GAS運用の設定画面は使用しない |

## 5. 操作性と信頼性

- 日付・時間・金額・必須項目・文字数はサーバーでも検証する。保存失敗や競合を通知する。API通信で専用失敗ハンドラーがない場合も、利用者にトーストを表示し無言で止まらないようにする。
- ライト／ダーク、文字サイズ、画面幅への適応、ロータリーの読込表示を維持する。全画面の視認性・iPad操作性は実画面で受け入れる。
- 勤怠「本日」は勤務状況・打刻・要確認・集計・月間カレンダーを優先し、操作履歴はボタンを押したときだけ表示する。勤務場所変更を含む履歴はSQLに保持する。
- API入力はUTF-8の実バイト数で2MiB以下とし、超過した受信を中断してSQLへ到達させない。不正なJSONや通信開始前の失敗も通知する。
- 全ページを自然な高さで表示する。画面高へ無理に押し込まず、収まらない内容はページの縦スクロールで到達できるようにする。警告バナー・大きな文字・短いウィンドウでも最下部を隠さない。
- 横に長い入力表は表の内側でスクロールさせる。縦に長い一覧は十分な表示高を確保して一覧内でスクロールできるようにする。カレンダーの週・凡例・保存ボタンを固定枠で切らない。
- ログイン画面・モーダル・通知メニューも表示領域を超えた場合にスクロール可能とする。
- 未認証・無効トークン・未対応メソッドでは全業務表を読まずに拒否し、ログアウトも業務表を読み込まない。退職・削除された社員の既存セッションは再開を拒否する。
- 不要な再読込と長い待ち時間を減らす。ログイン設定の架空担当者一覧は在籍社員の必要列だけを読む。通常の業務要求では引き続き全業務表を読むため、速度改善を完了したとは扱わない。改善は同じ条件で前後を計測する。
- テーマ・表示設定・選択担当者・セッショントークン以外の業務レコードをブラウザーの永続ストレージへ保存しない。保存の正本はSQLとする。

## 6. 検証と未受入事項

回帰テストはSQL初期投入・保存再取得・競合ロールバック、主要業務の読取と一部保存、HTTPセッション・権限・異なるOriginの拒否、配布HTMLの構文を確認する。テスト実装は`tests/`を正本とする。初版の回帰試験・型チェック・ビルド・公開後確認を改めて実行し、完了と未実施を分けて記録する。

| 未受入事項 | 完了の条件 |
|---|---|
| PDF・Excel・CSV正式発行、関連書類、添付 | Google接続なしで生成・保管・取得・権限・再試行を確認 |
| 外部照会・自動処理・バックアップ | Sites方式へ実装し、起動条件・復旧・失敗時挙動を検証 |
| 全画面・全業務操作 | デスクトップとiPad相当で導線、権限差、テーマ、エラー回復を確認 |
| SQL取得・更新の効率化 | 領域別取得と行単位更新を実装し、整合性と速度を確認 |
| 正式運用 | 本人認証、共有対象、権限、監査、バックアップ、会社の確定規程を別途受け入れる |

未対応事項を文書から消して完了と扱わない。現在の開発版の整理と、正式運用に向けた機能開発を区別する。
