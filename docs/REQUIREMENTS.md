# FM WORKS 要件定義書

**文書版:** 0.26.2
**更新日:** 2026-10-18

## 目的と今回の変更

FM WORKSは、勤怠・工数・案件・予定・申請・書類・経理・資金繰り・総務・社内文書をまとめる開発中の試作アプリ。ユーザーの2026-10-18指示により、公開先をGASからGPT Sites、DBをGoogle SheetsからSites内蔵SQL/D1へ変更する。スプレッドシートへの接続・既存実DBからの取込みは行わない。

## 必須条件

| ID | 条件 | 確認方法 |
|---|---|---|
| R1 | Sitesで公開できる | 同一project_idの公開結果を確認 |
| R2 | 保存先がSQL/D1である | SQLマイグレーション・D1 binding・DBテーブル一覧 |
| R3 | データはすべて架空 | SYNTHETIC_ONLYの初期データと生成元を確認 |
| R4 | 保存が再読み込み後も残る | APIをまたいだSQL読戻し |
| R5 | 同時保存で他の変更を消さない | 古いrevisionを使う保存が409で拒否され、原本が残る |
| R6 | Google接続なしで主要機能が動く | 外部サービスを拒否する環境でAPI統合テスト |
| R7 | 以前の画面・修正済み業務ルールを引き継ぐ | legacy sourceとSQLアダプターの組合せを検証 |
| R8 | 非対応機能を成功扱いしない | 移行中のAPIは501と説明を返す |

## データと利用者

5人の架空担当者（管理者・リーダー・社員）を選ぶ方式。ログイン画面に開発用であることを明記する。これは正式な社員認証の代わりになる製品仕様ではない。Sitesの公開範囲は所有者限定で開始する。

共有の架空DBに保存するため、ブラウザーを閉じても消えない。初期データは初回だけ投入する。新しい公開で既存の試作データを上書きしない。実社員名・給与・顧客・金融機関・口座・実務資料を入力しない。

## 機能の継承

ホーム、打刻、工数、プロジェクト、予定表、申請、見積下書き、経費、資金繰り、総務、社内文書を既存画面から継承する。社員・会社カレンダー・見積マスタは管理メニューから操作する。権限・入力条件・月次締め・改訂・監査の既存ルールをSQLでも維持する。

以前Google Drive/Spreadsheetファイル生成に依存していたPDF・Excelの正式発行、ファイル添付、旧バックアップ・自動トリガーは今回の基盤公開では移行中。動作確認済みの項目と未受入の項目はMIGRATION_STATUSで追跡する。

## 品質と更新

SQLには54業務テーブルと3つの管理テーブルを用意する。現在の表形式互換層を移行の足場とし、将来は業務領域別のSQL取得・更新へ分割する。互換層を完成した正規化設計と誤認しない。

GitHubは要件・設計・コード・PRの正本。Sitesのソース保管と公開を同期する。GitHubを更新しただけでSitesへ反映したと扱わず、Sitesの公開結果も確認する。GitHub Actions等の実行枠は使用しない。
