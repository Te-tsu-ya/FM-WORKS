確認材料：`src/Index.html`、`src/AppCore.html`、`src/AppHomePortal.html`、`src/AppOperations.html`、`src/AppPeopleMonthly.html`、`src/AppAdmin.html`、`src/Styles.html`、2026-10-08 提示のホーム実画面。

## 結論（監査と品質ゲートは別に扱う）

**現行アプリは共通デザインの土台があるものの、画面間の完全なUI/UX統一には未達。**

- 共通化されている：ブランドカラー・サイドバー/上部ナビ・ライト/ダーク・`.card`・`.primary-button` / `.secondary-button`・`pageHead()`・通知/モーダルの共通部品。
- まだ画面固有：カード内側の密度と余白、細字のサイズ、見出し周辺の構成、空状態/読み込み/失敗の案内位置、複雑な一覧の操作導線。
- 本版は最も頻繁に使うホームの1画面性と、共通のカード角丸を優先修正。**他画面の全面的な再設計や完全国際アクセシビリティ監査が完了したとは扱わない。**

## 2. 共通ルール

### 2.1 視覚と部品

- ブランド基準：`--bg`、`--surface`、`--surface2`、`--line`、`--text`、`--muted`、`--blue`、`--green`、`--orange`、`--red`。
- 大きなカード：`--fm-ui-radius-card = var(--radius)`（現状18px）、境界線は`var(--line)`、ベース面は`var(--surface)`。小さな入力・ボタンは12px程度の角丸を基本とする。
- 内容の区切り：4pxの倍数を基準に8/12/16pxを優先。意図なく9px・11px・13pxなどを増やさない。
- タイトル：ページタイトル約24〜28px、カードタイトル16px、本文は13〜14pxを基本。10〜11pxは補助ラベル/メタデータに限定し、重要な数字や説明には使わない。
- 「追加/登録/出退勤」は主操作 `.primary-button`、確認/移動/取消は状況に応じ `.secondary-button`。危険操作は別の明確な警告/確認を行う。
- エラー・未設定・期限注意はアイコンや文言を必ず付け、色だけに頼らない。数値が未取得なら架空値を表示しない。
- 画面内の英語見出し（ATTENDANCE/QUICK ACCESS等）は装飾的な小見出しとしてのみ使用。必要な操作名は必ず日本語にする。
- キーボード利用時は `:focus-visible` を確認し、機能の読み上げ順と視覚的な順序を一致させる。

### 2.2 ホームの1画面基準

- **PCの通常表示（幅1220 CSS px以上、高さ700 CSS px以上）**は、ホームの上部（挨拶・月次指標）、現在の勤怠、要対応、今日の予定、クイックアクセスの各見出し・主要操作がすべて一画面内で確認できる。
- 拡大率200%や細長いウィンドウ/小型端末では、無理に縮小せず通常スクロールに切り替える。1画面固定はアクセシビリティを犠牲にしない。
- 空状態で巨大なカードを引き伸ばさない。予定は最大2件をプレビューし、超過件数は「ほか○件」と予定表への導線にまとめる。
- 件数が増えた場合はカード内部のスクロールも許容するが、主要操作と関連画面への遷移は隠さない。
- 通常のクリックで新たな通信を増やさず、既存APIと認可ロジックを再利用する。

### 2.3 ページ単位の標準情報構造

| 画面 | 最優先の情報と行動 | 付随する情報 |
|---|---|---|
| ホーム | 勤務状態・次の打刻・要対応 | 月次指標・当日の予定・導線 |
| 勤怠 | 出退勤/休憩・打刻異常 | タイムライン・月次・履歴 |
| 工数 | 未入力時間・入力フォーム | タイムライン・履歴・案件 |
| 予定表 | 日付移動・表示切替・予定登録 | 社員フィルター・日別詳細 |
| 申請 | 新規申請・自分の履歴・承認待ち | 年休残数・年5日・ガイド |
| 管理 | 社員/権限・勤務ルールの確認/編集 | 関連ドキュメント・各種設定 |
