# FM WORKS｜共通UI/UXデザインシステム v1

**適用版:** 0.15.0  
**目的:** ホーム・勤怠・工数・予定表・申請・管理・事務を一つのアプリとして統一し、別画面の改修でもデザインや操作を壊さない。

## 1. デザインの原則

1. **主要操作優先** — 出退勤・申請・入力は一目でわかる位置に置き、補助情報は折りたたむ。
2. **共通性** — ナビゲーション、色、文字、カード、ボタン、入力欄の意味を画面間で統一する。
3. **状態を明示** — 読み込み中・0件・権限なし・保存前・成功・失敗を色だけでなく文字でも示す。
4. **小画面は順序も保証** — 見た目だけでなくHTMLの読み上げ順・キーボード順も自然にする。
5. **実データとデモの分離** — 例示データは必ずラベルと保存範囲を明示し、本番の残数や金額に混ぜない。
6. **勝手に権限を増やさない** — 権限はサーバーで算出し、サーバーの書き込み操作は別途権限検証を要する。

## 2. 共通デザイントークン

定義元は `src/Styles.html` の **FM WORKS Design System v1** セクション。

## 3. 画面別の約束

| 画面 | 最優先の操作・情報 | 統一するパターン |
|---|---|---|
| ホーム | 出退勤、重要な要対応、当日の予定 | 高さに合わせた情報密度、4つのKPI、2列 |
| 勤怠 | 勤務状態と打刻、勤務履歴 | 状態別カラーとテキスト |
| 工数 | 日付切替、クイック入力、時間帯 | 入力欄・保存・一覧・警告 |
| 予定表 | 月週日、社員、予定詳細 | 同じカラールール、クリックで詳細 |

| 事務 | 帳票・経費・出張・備品の入口 | 左モジュール一覧、右説明、未実装明示 |

## 4. 画面サイズ・アクセシビリティ

- **ホームの1画面表示:** 1366×768、1790×850、1920×1080、標準文字サイズ・100%倍率で主要機能と予定を視界に収めることを目標とする。画面内容や設定で収まりきらない場合はスクロールを許可し、絶対に切り捨てない。
- **拡大表示:** 125%、150%、200%、最大400%の拡大でも機能を失わない。大きい文字設定時は1画面固定より可読性優先。
- **スマホ:** 760px以下は主要カードを自然に縦並びにする。大きな入力欄はフォント16px以上を基本とする。左右にはみ出す表は内側だけスクロールできるようにする。
- **キーボード:** タブ順が視覚的な順序に一致する。フォーカスは `var(--ui-focus)` を使った2px以上のアウトラインで見える。
- **ライト／ダーク:** SVGロゴの `fill=currentColor` を利用しCSSで白黒を切り替える。ロゴ画像の色を固定しない。
- **色だけで状態を示さない:** エラーには「確認が必要」、完了には「完了」など文字を併記。
- **減速動作:** `prefers-reduced-motion` を尊重し、必須でない動きを抑制する。

## 5. コンポーネントの再利用と禁則

**再利用:** `.page-head`, `.eyebrow`, `.card`, `.primary-button`, `.secondary-button`, `.field`, `.badge`, `.muted`。

**禁則:** 同じ目的の新色をページごとに増やす、意味のない空白をカードの高さで埋める、クリックできない要素をボタンに見せる、補助文字を11pxより小さくする、権限なしで管理項目を描画する、実データとダミーを一緒に扱う。

## 6. 改修時の品質ゲート

- 全7画面のナビゲーション・操作ラベル・カード・補助色・入力UIを比較する。
- 権限別（一般社員、総務部署、管理者）にメニューを比較する。
- ライト／ダークのFMロゴを確認する。
- ホームで予定0件／要対応0件／多件数／読み込みエラーを比較する。
- PC・タブレット・スマホでレイアウトとスクロールを確認する。
- 新機能は既存CI検証に加え、データ取得と書込み権限のサーバー側検証を必須とする。

**検証の区別:** CIの静的・ロジック・契約テスト成功と、実ブラウザ目視・端末テストは別の判定として記録する。


## 7. 経理機能 v0.13.0

- 管理者・経理・総務だけに「経理」を表示し、一般社員は既存「申請」内の自分の経費・出張入力を利用する。
- 既存デザイントークンを使用して、カード、入力、主要ボタン、フォーカス、ライト／ダークを揃える。視覚デザインの詳細調整は次回実施する。
- 空・読込・権限不足・DB初期化前・エラーを文字で区別し、モバイルは入力列を一列にする。
- 金額の操作では自己承認を防止し、銀行振込と精算記録の違い、証憑原本保存が別途必要なことを表示する。

- 「事務」の経費・出張・証憑は、経理権限のある利用者に「経理を開く」導線を表示する。権限のない人には対象のデータや保存画面を描画しない。


## 8. 経理の確認・差戻し画面（v0.13.1）

- 承認前に入力済みの金額・理由・証憑・出張成果などを確認できる詳細ダイアログを提供する。長文でも省略せず閲覧できる。
- 差戻された申請は理由を提示し、社員本人が元の入力値から修正・再申請できる。未承認以外の書換え不可。
- 経費の証憑整理番号と金額を画面で照合し、画像原本の確認完了と混同させない。
- 承認待ち優先の表示、追加読込と件数表示を提供。PC／モバイル・ダーク／ライトの既存デザインを継承する。


## 9. レスポンス重視の画面操作（v0.13.2）

- タブ・画面は押した直後に描画し、ページ遷移の演出で操作を妨げない。
- すでに取得済みの月次・工数は再びローディング表示を挟まずに表示する。
- 新しい年月・社員を表示する際、直前に表示していた人や月の数値を新しい見出しの下へ載せない。
- キャッシュの再利用は短い時間のみ。利用者向けの明示的な「更新」を用意する。


## 10. 案4＋案3の事務・経理レイアウト（v0.13.3）

- 最初の3秒で「新規申請」「処理待ち」「業務選択」が見つかるよう、上部にクイック操作、左に6機能、中央に要対応、右に最近の記録とショートカットを置く。
- 業務を選んだら左の機能メニュー、中央の一覧、右の詳細へ切り替え、戻るボタンで事務トップへ戻れる。
- 既存の--text、--muted、--blue、--surface、--line、--ui-radius-card等で画面全体を統一。個々の記録状態は承認待ち・承認済・差戻し・精算済の文字と背景色を併用する。
- 1520px以下の事務トップは2列で補助情報を下段へ、960px以下は1列。1180px以下の業務詳細では機能メニューを上へ、960px以下で一覧→詳細を縦に表示する。
- 操作可能なボタン・検索・フィルターは可視のfocus状態を持ち、40px以上の操作面を確保。狭い画面でタップできないボタンや横にはみ出すテーブルを作らない。
- 値のないKPIを「0件」と偽装しない。0件／取得前／エラー／権限不足／DB未初期化を説明する。計画中の機能には保存できるような見た目を与えない。

- スマホでは対応待ちを上へ移動し、視覚順とキーボード・読み上げ順を一致させる。Chrome画面検証では日本語フォントを読み込み、文字化けした描画を品質証拠としない。

## 11. モバイルタイトル（v0.13.4）

- 事務トップの短い見出し「事務・経理」は390px幅で1行に保ち、説明文は次の行に配置。タイトルとキャッチコピーが互いの幅を奪わないようにする。


## 12. 見積作成のUI・UX（v0.14.0）

- 全社員に独立した「見積」メニュー。見積履歴・新規作成・明細編集・正式発行・PDF/Excel出力へ自然に移動する。
- 取引先選択で名称とインボイス番号を確認。品名/数量/単位/単価を最大21行登録。値引きはマイナス単価、注記行は計算対象外。小計/税額/総額を画面内で即計算するがサーバー側で必ず再計算。
- 変更が未保存なら正式発行ボタンを無効化。登録済み過去番号が管理者未確認の場合も正式発行できない。
- 非対応の元Excel帳票（請求・納品・注文・領収書）を有効な発行ボタンで偽装しない。
- 760px以下は明細行をカード型にして横はみ出しを回避。既存UIトークン・ダーク/ライトを継承する。

- 見積一覧・編集・発行後のPC/モバイル表示をChromiumで実測。390px画面で横はみ出しやボタンの押しにくさがないことを確認して公開する。

## 13. 9画面の統一デザイン（v0.15.0）
- 2026-10-09にユーザーが承認したホーム、申請一覧、経費申請、出張報告、見積一覧、見積編集、発行済見積、経理、管理設定の画面イメージを指針とする。
- 左メニューは日常業務/申請・帳票/管理業務/システム管理の4グループにする。権限のないリンクを表示しない。
- トップの説明、検索/絞込、数値カード、一覧/詳細、実行ボタンを共通の色・角丸・余白・読みやすい文字サイズで構成する。
- 入力はPCで主フォーム＋右概要、スマホで縦1列。画像アップロード等の未実装機能はクリック可能に見せない。
- 状態やエラーは色だけで示さず文字でも案内する。指標は実データか未取得（—）のどちらか。

- v0.15.0の画面QA: 1366×768、1440×900、390×844の実DOM検証を行い、ホーム1画面・見積・経費・出張・経理・取引先設定の操作・横幅・読みやすさを確認する。新しいUI CSSを実際のIndex同様に読み込んで確認する。

## 14. 総務 D+B ハイブリッド（v0.18.0）
- D案の対応待ち優先ダッシュボードとB案の検索/一覧/詳細を組み合わせる。既存の色・カード角丸・共通サイドバーを維持。
- 操作タブは総務ホーム、備品台帳、貸出・返却、購買管理、書類整理の5種類。
- 画面の件数はサーバーが保存したデータのみ。架空デモは「本番に保存されない」を常時明記。
- 検索・フィルターはローカル操作、通信なし。スマートフォンでは一覧・詳細を縦積みにする。

- 購買の「差戻し」は本人の詳細画面に修正・再申請ボタンを表示する。他人の申請や承認済の申請には出さない。
- 総務台帳の一覧は更新日時順。備品の保有数と貸出可能数を別の意味で表示し、初回DB未設定は管理者に専用の設定導線を示す。

## 15. 総務の高速操作（v0.18.2）
- タブ選択と条件検索は常に即時に更新する。ローディング中は旧「設計中」のページへ切り替えず、総務の読み込み状態のみを表示する。
- 台帳は最大60件ずつ表示し、さらに表示操作でも画面を切り替えず一覧と詳細のレイアウトを保つ。60件を超える場合は残件数を示す。
- バックグラウンド更新時は従来の一覧・選択中の詳細を維持し、通信障害が発生しても空画面にしない。


### 社内文書ライブラリ：統一画面（2026-10-10）

- 統合ナビゲーション「社内文書」に「業務フォルダ → 文書一覧 → 本文プレビュー」の3ペインを設置。既存の共通サイドバーを増設しない。
- 配色はアプリ共通の --surface / --line / --text / --muted / --blue のテーマトークンを使用する。
- フォルダは2階層、文書種類・公開状態・タグは別属性。分野別ショートカットは検索エリアの直下。
- 幅1120px以下はフォルダと一覧、下段に本文。幅760px以下は単一パネルの段階表示で、戻るボタンを用意する。
- 入力検索は一覧領域のみ再描画してフォーカスを保ち、長文は選択時に取得する。


### 社内文書・視認性と安全な操作（2026-10-10）

- 部門フォルダ内の検索開始時にも全フォルダ検索へ自動移行し、検索欄へのフォーカスを維持する。
- 編集中の未保存状態は画面内に表示し、取り消しや他メニューへの移動を確認する。
- ダークテーマの公開・下書きバッジは高コントラストの固定色を採用し、通常文字の比率4.5:1以上を必須とする。
