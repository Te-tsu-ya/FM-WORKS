# FM WORKS 全画面UI/UX統一性監査（2026-10-08、v0.11.10）

## 結論
**現状は一部統一／全面統一は未達。** ソースコードと提供された画面キャプチャに基づく監査であり、実端末の画面遷移・色差・拡大率を網羅して検査したという意味ではない。

| 領域 | 現状と根拠 | 判定 | 対応 |
|---|---|---|---|
| 全画面共通シェル | AppShell、Index、Styles がサイドバー、トップバー、コンテンツを共有 | おおむね統一 | 現状維持 |
| ブランド色・基本テキスト | Styles のテーマ変数を各画面で共通使用。一部の個別セクションで直接色値を指定 | 部分統一 | 変数を正本とし個別色を段階削減 |
| カード・角丸・影 | card 共通部品がある一方で各画面独自カード（home-portal、request、admin、worklog）に異なる角丸・余白が存在 | 要改善 | カードの密度・角丸・境界線の共通ルールを段階的に適用 |
| ボタン | primary-button、secondary-button、compact 等は共通。個別のクリック可能要素に任意のスタイルあり | 部分統一 | 本版で全画面の focus-visible を追加。次版でサイズ・状態表現を標準化 |
| フォーム | field、form-gridを横断利用。一部の社員ウィザード・申請・管理の固有フォームに異なる説明文密度あり | 部分統一 | 必須・エラー・確認・保存中の標準化を別改修に |
| サイドバー・ナビゲーション | 左サイドバーは共通。管理はサイドカテゴリ、予定表は表示切替、申請はカード中心でナビが異なる | 役割に応じて差あり | 異なる機能の操作方法まで無理に同一化しない。タブ・アクティブ色・戻る動作をチェック |
| ホーム | 固定高3カラムの空白は解消済みだが、スクリーンショット（1792×850）では下段ショートカットが画面外 | 不適合 | 本版でPC向け密度を調整 |
| 勤怠・工数 | 勤怠には勤務時間の実績と編集、工数は作業時間・案件別表示が中心。文字や配置は業務特性に合わせて異なる | 機能設計として許容 | 基本コンポーネントとステータス色をそろえる |
| 予定表 | 月・週・日・一覧など高情報密度の専門UI。予定の色は担当者・分類に意味がある | 目的上の差を許容 | 共通フィルター、ローディング、空状態の扱いを監査 |
| 申請 | ダッシュボード・申請種別・承認・履歴の複合画面。年休の警告・期限色を追加 | 部分統一 | 見出し、空状態、エラー時の扱いを横断チェック |
| 管理 | 専用縦ナビゲーション、社員マスタ・詳細・4ステップ登録。ホームとの違いは管理作業の性質に由来 | 構造差は合理的 | 共通の入力密度・タブ・通知パターンに集約 |
| レスポンシブ | 多数の @media により個別画面で対応。実端末・拡大率の全画面検証ログはなし | 未検証 | PC / タブレット / スマホ、80/100/125/150/200%検証を残タスク |
| アクセシビリティ | ラベル、focus-visible の実装は画面ごとに差がある | 要改善 | 本版で共通フォーカスを適用。コントラストとキーボード操作の実機試験は未完了 |

## 共通デザイン規約（今後の正本候補）
1. **色:** primary、surface、surface2、text、muted、line と注意・危険・成功の意味色をテーマ変数経由で指定。社員/予定の色分けは意味を維持する。
2. **カード:** 標準は12〜16px角丸、境界線1px、内側余白12〜16px（密度によって段階選択）。同じ画面の同じ役割のカードには同じ余白・角丸。
3. **文字:** 本文12〜14px、画面見出し20〜24px、主要な数値20〜28px。10〜11pxは補助情報に限定し、主要操作には使用しない。
4. **操作:** 主操作は塗りつぶし、補助操作は枠線、危険操作は確認付き。クリック可能な面には hover/focus/disabled/loading の区別を設ける。
5. **空・読込・失敗:** 0件では大きな空白を作らず、簡単な説明と適切な次の行動を表示。読込中・失敗・再試行を区別する。
6. **画面高さ:** **ホーム**は1792×850相当の標準PCで最重要操作が第一画面に見えることを目標。作業画面（申請・管理・工数）は情報の欠落を避け、スクロールを許容する。倍率拡大/低高さでは無理に一画面へ押し込まない。
7. **レスポンシブ:** キーボードのTab移動順＝画面上の読み順。タッチ操作面の高さは原則40px以上を目標。
8. **表示権限:** 承認待ちや管理者への導線は認証情報に従う。権限のない人に集計データを返さない。
9. **状態変化:** 保存後・取得後・処理失敗時に理由を表示し、データを勝手に推定しない。

## この版の品質チェック
- 静的検査：既存パイプラインの検証、home-fit CSS の存在とメディア条件を確認。
- 単体/クライアント契約：既存のすべての自動テストを再実行する。
- **未実施:** 実ブラウザのピクセルベース高さ測定、実際の個人/管理者アカウントでの通し操作、全画面の目視比較。これらが済むまで「全画面UI統一完了」とはしない。
