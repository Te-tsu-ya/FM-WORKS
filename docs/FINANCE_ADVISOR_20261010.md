# 経理・支出分析・旅費説明・インボイス照会｜運用設計（2026-10-10）

## 目的とデータ境界

- **支出分析:** Google Sheets「事務所で必要なもの」→「経費」のA:Jを読み取り専用で分析する。列B「経費種別」は実際には「2023年10月」のような年月であり、会計上の勘定科目と扱わない。利用日（A）、取引先（C）、品目（E）、利用金額（F）、支払者（H）、支払方法（I）を使用。
- **精算申請・出張旅費:** 既存FM WORKS DBの「経費精算申請」と「出張報告」に保存する。旧台帳の行は移行・複写・変更しない。
- **二重計上の防止:** 旧台帳とFM WORKSの支出記録・精算申請は重複する可能性があるため、年間金額を合算せず、出典が異なる別画面で表示する。
- **税理士向け:** 事業者ごとの分類・経理仕訳・税額・保存義務の最終判断は税理士へ。支出分析は社内の支払者・用途を追う管理用であり、会計試算表ではない。
- **権限:** 支出分析とインボイス照会は総務・経理・管理者のみ。社員自身の出張参考計算は本人の認証情報にひもづける。

## FM WORKS経理画面での操作

1. 経理画面で「支出分析・旧台帳」を押すと、初めて旧シートへアクセスする（承認画面の初回表示を遅くしない）。
2. 年を切り替え、月別の支出、支払者別、取引先別、購入品目別を確認する。年の全件で集計し、一覧は直近160件のプレビュー。支払者フィルターと検索はブラウザ内で追加通信なし。
3. 「経理に戻る」で既存の承認・精算・経費記録へ戻る。旧シートには書き込まない。
4. 経費記録の登録画面でT＋13桁を入力して「番号を照会」。国税庁のAPIアプリケーションIDが未設定なら、エラーと公式検索サイトへのリンクを表示し、会社名を作り出さない。
5. 取得した事業者名は自動で上書きせず、「取引先欄に反映」を押して登録する。公表情報は取引日・取引内容の正当性を自動保証しない。
6. 出張申請画面の「旅費の計算根拠」で片道距離（km）と宿泊実費を入力し、規程の内訳を表示する。確定可能な参考計算だけを「備考欄へ根拠を転記」で保存する。未確認なら警告して承認者の確認を促す。

## 旅費規程と旧シートの差分

- 参照基準：『旅費規程_完成版_2025.12.1.docx』、社内規程2025-12-01適用。
- 日帰りNo.1は**原則片道100km以上**、役職「代表」なら5,500円。片道100km未満・日帰りで早朝夜間出張に該当する場合はNo.3〜No.5のみが原則。
- 会社所有車でなく私有車の場合、承認済み移動に37円/kmの規程があるが、距離・承認・交通費の別計算のため現行フォームでは自動加算しない。
- 宿泊は役職・地域の**上限額がそのまま支給額にはならず、領収書に基づく実費**。上限超過は別途承認確認。
- 複数日の日当と早朝夜間の重複は**日別上限確認が必要**。簡易フォームでは確定値にせず警告。
- 既存の出張記録は「30km以上」の列と役職別VLOOKUP＋宿泊上限×泊数の式で計算されており、規程の100kmおよび実費と不整合の可能性がある。既存支払履歴は**変更しない**。支払内容を再判定する場合は責任者と税理士が原本と当時の規程を照合する。
- 計算結果は規程に基づく**参考値**であって税務上の非課税・精算承認ではない。ユーザーが入力した情報と承認日、規程バージョンを備考へ保存する導線を設ける。

## インボイスAPI運用

- 公式： https://www.invoice-kohyo.nta.go.jp/web-api/index.html
- 国税庁の公式APIを使用するにはアプリケーションID（13桁）が必要。Google Apps Scriptの**スクリプトプロパティ `NTA_INVOICE_API_ID`**へ管理者が設定する。アプリソース／HTML／ブラウザには保存しない。
- 使用API： `https://web-api.invoice-kohyo.nta.go.jp/1/num?id=...&number=Txxxxxxxxxxxxx&type=21&history=0`、登録番号形式をサーバーで検証。
- API未設定／無応答／未公表／名称欠落は成功扱いにしない。取得元の表示・確認日を伴わせ、公式検索への導線を残す。
- 公表情報を利用したサービスとしての注意書きは国税庁の利用規約に従うこと（出典：国税庁の公式API）。

## 設定と障害対応

- 旧支出台帳IDは既定で共有済みの参照先を使用。必要に応じてスクリプトプロパティ `FM_LEGACY_EXPENSE_SPREADSHEET_ID` で安全に上書きできる。
- Webアプリの実行アカウントに旧台帳の閲覧権限がない場合、取込成功を偽装せず、画面に明示する。
- 元台帳A:Jの見出しが違う場合は集計しない。日付不正や利用金額不正がある場合は集計しなかった件数を表示する。
- 大きな元台帳は年度ごとにサーバーで集計。2分間の短期キャッシュを使い、未選択の画面で一切読み込まない。
- ローカルのユニットテストはGoogle Sheetsと国税庁Web-APIの偽応答のみ。実API接続と本番データ変更は行わず、API ID発行後に検証環境で受け入れ確認する。

## 品質ゲート（試験要件）

- 月別・支払者別・取引先別・品目別の集計が全件の合計と一致し、当年以外が混入しない。
- 閲覧権限のない社員は他人の旧支出台帳を取得できない。
- 規程と乖離した「30km以上」は片道100km以上として扱わない。宿泊費が上限より低い場合は実費を使用し、条件不十分なら確定金額は出さない。
- 国税庁API ID未設定／不正番号／取得失敗時は存在しない会社名を返さない。API IDはレスポンスに含めない。
- 既存の経費・出張申請・承認・精算および他メニューの回帰テストが合格する。
