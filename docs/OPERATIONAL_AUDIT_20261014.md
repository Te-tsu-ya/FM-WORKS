## 採用した性能改善

| 比較案 | 判断 | 理由 |
| --- | --- | --- |
| 画面別メモリーキャッシュの活用 | 維持＋不具合修正 | 工数期間、予定期間、月次、見積、経理、総務、プロジェクトで既に存在。期限だけを延ばさない |
| 同一進行中RPCの共有 | 採用 | 同じ内容を別経路から要求しても通信・GAS起動は1回。保存後は別世代、結果の複製とログイン分離 |
| 全ページの一括先読み | 不採用 | 未使用の業務APIが操作中の通信と競合し、待ち時間と負荷が増える |
| 静的HTMLの版別キャッシュ | 採用 | 暖機後のIndex評価・各includeの再生成を省く。業務データと認証は含まない |
| 全Sheets結果の長期キャッシュ | 不採用 | 権限変更や保存結果の整合性を損なう。認証と更新時の最新版照合を残す |
| プロジェクト詳細の範囲取得 | 採用 | 対象案件の本文だけ取得。全案件の別名衝突判定は維持 |
| DB・実行基盤の全面移設 | 今回は保留 | CTOと共有DBの選定が未確定。既存データを安全に使い、今回の改善効果を先に検証する |

公式根拠: [サービス呼び出し最小化・キャッシュ](https://developers.google.com/apps-script/guides/support/best-practices)、[非同期RPCの順序と上限](https://developers.google.com/apps-script/guides/html/communication)、[Cacheのサイズ・消失](https://developers.google.com/apps-script/reference/cache/cache)。
