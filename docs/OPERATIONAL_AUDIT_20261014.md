# FM WORKS 実運用・読込み監査（2026-10-14）

対象正本: main f7af12d29437c6d1db43201f1399a67429f2fc28、アプリv0.25.5／GAS公開版193の記録。修正版v0.25.6。

## 採用した性能改善

| 比較案 | 判断 | 理由 |
| --- | --- | --- |
| 画面別メモリーキャッシュの活用 | 維持＋不具合修正 | 工数期間、予定期間、月次、見積、経理、総務、プロジェクトで既に存在。期限だけを延ばさない |
| 同一進行中RPCの共有 | 採用 | 同じ内容を別経路から要求しても通信・GAS起動は1回。保存後は別世代、結果の複製とログイン分離 |
| 全ページの一括先読み | 不採用 | 未使用の業務APIが操作中の通信と競合し、待ち時間と負荷が増える |
| 静的HTMLの版別キャッシュ | 採用 | 暖機後のIndex評価・各includeの再生成を省く。業務データと認証は含まない |
| 全Sheets結果の長期キャッシュ | 不採用 | 権限変更や保存結果の整合性を損なう。認証と更新時の最新版照合を残す |
| プロジェクト詳細の範囲取得 | 採用 | 対象案件の本文だけ取得。全案件の別名衝突判定は維持 |
| DB・実行基盤の全面移設 | 今回は保留 | CTOと共有DBの選定が未確定。既存データを安全に使い、今回の改善効果を先に検証する |

公式根拠: [サービス呼び出し最小化・キャッシュ](https://developers.google.com/apps-script/guides/support/best-practices)、[非同期RPCの順序と上限](https://developers.google.com/apps-script/guides/html/communication)、[Cacheのサイズ・消失](https://developers.google.com/apps-script/reference/cache/cache)。

| A-01 | 技術: 起動ごとに静的HTMLを全評価 | 版別のUTF-8分割キャッシュ。欠損・停止・別版をテスト |
| A-02 | 技術: 同一進行中RPCの横断的な重複 | 1回の通信を共有。別引数・保存後・失敗・ユーザーオブジェクトを検証 |
| A-03 | セキュリティ: 旧RPCの認証エラーが次のログインを終了させ得る | reset世代で旧成功・旧エラーを遮断 |
| A-04 | セキュリティ: 通知・全体更新が旧社員の応答を適用し得る | token/data参照照合。ログイン変更・同一セッション再初期化に対応 |
| A-05 | 業務: ホーム再訪で無効化された集計が更新されない | ホーム遷移でTTLと更新状態を確認 |
| A-06 | 業務: 書類履歴への直接起動時に取得しない | 見積・書類履歴を同じ取得対象へ追加 |

| A-09 | データ喪失: 見積・経費・工数等を再読込／ログアウトで喪失 | 未保存確認、保存中／結果未確認はログアウト不可。永続保存はしない |
| A-10 | 技術: 詳細で他案件の作業本文や資料用ID列を転送 | 共通索引で一致行だけ読取。実シート行番号保持、索引不可時fallback |
| A-11 | UX: 台帳更新時に既存一覧を消す／ページキャッシュが増加 | 同キー表示保持、別キー旧表示禁止、40件上限 |

## 検証と公開の区別

GPT環境で `node scripts/run_local_checks.mjs --functional`: **49 PASS / 0 FAIL / browser12 SKIP**。構文、版整合、配色、勤怠・工数・予定・承認・月次・見積・経理・資金繰り・総務・文書・プロジェクト・デモ・同期・再試行を回帰検証。

新規合成計測: 同じ2件の取得を1件のRPCで処理。1000件中2件の一致本文だけを取得（転送データ6セル）。暖機後の静的HTML評価は0回。これらは構造上・合成データの検証であり、実GASでの秒数・P50/P95ではない。

ブラウザー用Chromium実行ファイルがGPT環境にないため12画面テストは未実行。GASエディターのGoogleログインが切れており、再接続後に既存URLへ公開する。公開・実操作の完了は別のrelease記録に記載する。GitHub Actionsは使用しない。

## 本番開始前に残る事項

- 公開アクセスは「自分のみ」の確認用運用。社内展開には対象ユーザー・組織・個別認証を決めてから変更する。
- 試作モードを終了する本番ENV・個別PIN設定、会社カレンダー／入社日／承認者／労務規程・年休運用の会社固有条件を確定する。
- 実バックアップの認可・復元演習、主要入力と保存→一覧→集計の認証付き実操作、ライト/ダーク・PC/スマホ表示、実データ量でのP50/P95を受け入れる。
- CTO説明用の架空JSONとGAS既存Sheetsは別構成。共有DBの本導入方針、同時運用、ファイル保管・監査・運用責任者を確定する。

コード修正・GitHub統合・GAS公開・DB移行・実操作は別々の証拠として扱う。未確認の条件を「実運用完成」「瞬時表示」と報告しない。
