# FM WORKS UIデザインシステム / 横断監査

**版：0.11.10 / 2026年10月8日**

## 1. 目的と適用範囲
ホーム・勤怠・工数・予定表・申請・管理を、単一のFM WORKSとして自然に操作できるようにする。UIの統一とは単に同じ青色を使うことではない。操作・状態・余白・文字・視認性も含む。

## 2. コード監査の結果

| 画面 | 既存の強み | 発見した不統一・操作上の問題 | v0.11.10での対応 |
| --- | --- | --- | --- |
| ホーム | 4指標・タスク・出退勤が1か所に集まる | 自然スクロールによって、予定とショートカットがPC画面から外れていた | 標準PCに限定した1画面フィット、カード内スクロール、小画面のフォールバック |
| 勤怠 | 押すべき出退勤ボタンが目立つ | カード半径18px、影・見出しが別体系 | 共通のカード角丸・影・見出し規約へ |
| 工数 | タイムラインと入力を色で区別できる | パネル角丸16px、操作・表示の濃さが部分ごとに異なる | 共通のカード・フォーカス規約へ |
| 予定表 | 社員色、土日祝日を使い分ける | 詳細パネル半径17px。カレンダー特有の密度を持つ | パネル外形をそろえ、休日・社員色は用途上の例外として維持 |
| 申請 | 申請種類の色と進捗が分かりやすい | カード半径17px、操作入口によって余白が異なる | 主要パネルの外形とボタン規約を統一。申請種類の色は維持 |
| 管理 | 社員一覧と詳細の分離・ガイド登録 | 主要パネル半径15px、管理内だけ濃淡が別 | 共通カード外形と操作フォーカスへ |

監査はGitHubの現行ソースと提供された画面写真に基づく。全端末の実機目視を完了したという意味ではない。

## 3. デザイントークン

| 項目 | 仕様 | 意図 |
| --- | --- | --- |
| ブランドの主色 | `--blue` | クリック・選択・注目点 |
| 警告 | `--orange` / `--red` | 要注意・危険（色に加え説明文を付与） |
| 背景・カード | `--bg`, `--surface`, `--surface2`, `--line` | 明暗テーマで自動追従 |
| 補足テキスト | `--muted`：明色テーマでは#62748d | 白背景でもコントラストを確保 |
| 主要カード | `--ui-card-radius:16px`, `--ui-card-shadow` | 6画面で共通の輪郭 |
| ボタン | `--ui-control-radius:10px` | 行動できることが分かる一貫性 |
| 操作領域 | `--ui-control-min-height:40px` を推奨 | タッチ・マウス操作の失敗低減 |
| セクション間隔 | `--ui-section-gap:12px` | 情報のまとまり |
| セクションタイトル | `--ui-section-title-size:16px` | 見出し階層 |
| キーボード | `--ui-focus-color:var(--blue)`、3pxリング | 迷わず操作できる視覚フィードバック |

## 4. 画面の使い分け

- **ホーム**：まず何をするかを明確に。PC標準表示は1画面、利用データが長いカードだけ内部スクロール。少ない予定を無理に拡大しない。
- **勤怠・工数**：作業効率重視。PCでは入力と確認を同時に見せる。文字拡大・小画面はスクロールを許す。
- **予定表**：月・週・日で情報密度が異なるため全表示を1画面固定にしない。休日・社員色は認識補助として保存する。
- **申請**：種類・理由・承認状況が分かれる。手順を先に見せ、詳細は必要なときに表示する。
- **管理**：一覧から個別詳細を選ぶ構造。危険操作は確認を挟む。
- **全画面**：空・読込中・失敗・完了を区別し、操作可能な部品はフォーカスと反応を提供する。

## 5. ビューポートと検証方針

- 標準PC：1792×854、1366×768、1440×900 CSS pxを対象とし、通常文字サイズならホームの主要4パネルがブラウザ内に入ること。
- タブレットとスマホ：1100×700、390×844。情報が見切れないこと、横方向スクロールがないことを優先。縦スクロールは許容。
- 文字サイズ「大」：ホームも自然スクロールし、文字の欠けを防止。ブラウザ拡大時も同様。
- Chromeの実ブラウザチェックと、既存クライアント契約/ロジック試験を両方実行。自動テストの模擬画面と実データを使う確認は別扱い。
- WCAG 2.2 `2.5.8` の最低24×24 CSS px（例外あり）を参照し、主要操作は原則40px以上を目標とする。<https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum>

## 6. 今後の改修ルール

1. 共通トークンで表せるカード・ボタン・フォーカスを個別CSSで重複定義しない。
2. 画面の高さ固定は、見切れないことを実ブラウザで検証できる場合のみ採用する。
3. 新規ページでは、空・読込中・エラー・成功・モバイル・ダークの状態を検証する。
4. 共通部品の修正後は、ホーム以外の勤怠・工数・予定表・申請・管理の回帰テストを実施する。
5. 実機確認していない条件を「確認済み」とは書かない。
