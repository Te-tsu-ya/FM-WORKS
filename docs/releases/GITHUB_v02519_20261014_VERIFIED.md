# v0.25.19 案件工数取得・復旧・内部情報の検証記録

基準main: `abafec42ae69a370e0f8633f614bb78702dc93cb` / v0.25.18。今回実コード・要件/設計の版をv0.25.19へ更新。

## 改修

- 大規模台帳の案件詳細は選択案件の現名/過去名を検索し、一意に一致する工数行だけを読取る。6,000行中の対象8行の試験では本文104セルを取得し、従来の全件78,000セルを取得していない。これは本文セル数であり、GAS通信秒数の測定ではない。
- 小規模250行以下、有効な全件キャッシュ、対象が広く散在して取得窓が台帳の70%を超える場合は既存の一括処理を維持。最大8窓、検索未対応時は案件E列だけを先に取得。正規表現記号、大小文字、Unicode空白、旧名、同名衝突、移動済み候補を検査する。
- 更新前の詳細要求が新規取得をブロックする問題を要求チケットで修正。旧完了が新pendingを削除しない。通常の5分キャッシュと下書き保持は維持。
- 別案件/不正形式の応答をキャッシュせず、明示的な「詳細を再試行」で案件詳細だけを再取得。別の選択案件の失敗で現在画面のエラーを上書きしない。
- 経理と案件の読取応答から内部送信キー、案件から物理行番号も削除。正本を変更せず、ID/改訂/更新日時と保存時の権限・競合・監査・冪等性を保持。
